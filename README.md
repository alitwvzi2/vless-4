# پنل مدیریت VLESS — نسخه‌ی حرفه‌ای (بدون xray-core، بدون TCP Proxy)

پنل مدیریت چندصفحه‌ای برای VLESS+WebSocket که مستقیم در پایتون پیاده‌سازی شده (بدون باینری
`xray-core`). چون همه‌چیز از طریق یک وب‌سرور معمولی (FastAPI/uvicorn) روی WebSocket رد می‌شه،
روی دامنه HTTPS پیش‌فرض Railway (`*.up.railway.app`) کار می‌کنه — بدون نیاز به فعال‌کردن TCP Proxy.

## قابلیت‌ها

**داشبورد و ناوبری**
- منوی سایدبار سه‌بخشی: نمای کلی، کاربران، تنظیمات (روی موبایل به نوار افقی تبدیل می‌شه)
- نمای کلی با آمار زنده: تعداد کاربران، کاربران فعال/منقضی، اتصالات آنلاین لحظه‌ای، کل ترافیک، آپتایم سرور، لیست پرمصرف‌ترین کاربران

**مدیریت کاربر**
- افزودن/ویرایش/حذف کاربر، فعال و غیرفعال کردن
- **تاریخ انقضا** برای هر کاربر (خودکار قطع می‌شه بعد از سررسید)
- **محدودیت حجم مصرف (GB)** با نوار درصد مصرف؛ بعد از اتمام سهمیه خودکار قطع می‌شه
- **ریست ترافیک** تکی یا همه‌ی کاربران با یک کلیک
- **بازسازی لینک (regenerate UUID)** برای باطل کردن لینک قدیمی بدون از دست دادن تاریخچه‌ی کاربر
- یادداشت دلخواه برای هر کاربر (مثلاً تاریخ خرید یا شماره تماس)
- وضعیت آنلاین/آفلاین لحظه‌ای هر کاربر

**لینک‌ها**
- ساخت خودکار لینک `vless://` برای هر کاربر
- **ساب‌لینک اختصاصی** (`/sub/{uuid}`) با خروجی base64 استاندارد، سازگار با v2rayNG /
  NekoBox / Hiddify / Streisand — فقط کافیه ساب‌لینک رو در کلاینت وارد کنی، دیگه لازم نیست
  خودت لینک تکی رو کپی/پیست کنی و اگه UUID عوض بشه (regenerate)، کلاینت خودش آپدیت می‌گیره
- **QR Code** اختصاصی هر کاربر برای اسکن سریع با موبایل

**تنظیمات کانفیگ (پنل‌محور، مثل RVG/3x-ui)**
- یک بخش «تنظیمات کانفیگ» در صفحه‌ی تنظیمات که روی **همه‌ی** کاربرا (قدیمی و جدید) یکجا اثر می‌ذاره:
  - **پورت** لینک VLESS
  - **Security** (`tls` یا `none`)
  - **ALPN** (`h2,http/1.1` / `h2` / `http/1.1`)
  - **Fingerprint (fp)** با گزینه‌های `chrome`, `firefox`, `safari`, `ios`, `android`, `edge`, `random`, `randomized`
  - **مسیر وب‌سوکت** — قابل تغییر از داخل پنل، **بدون نیاز به Redeploy** (چون خودِ اپ همیشه
    مسیر رو از تنظیمات لحظه‌ای می‌خونه)
  - **SNI سفارشی** (اختیاری؛ پیش‌فرض همون دامنه)
- چون هر لینک `vless://` لحظه‌ای از همین تنظیمات ساخته می‌شه (نه اینکه موقع ساخت کاربر فریز بشه)،
  با هر تغییر تنظیمات، لینک همه‌ی کاربرای قبلی هم خودکار به‌روز می‌شه.

**دسته‌بندی / گروه‌بندی کاربران**
- هر کاربر متعلق به یک **گروه** (مثلاً «عمومی»، «VIP»، «تست») هست.
- در صفحه‌ی کاربران، بالای لیست **تب‌های فیلتر گروه** هست (با تعداد کاربر هر گروه).
- در فرم افزودن/ویرایش کاربر می‌تونی از گروه‌های موجود انتخاب کنی یا یک گروه تازه تایپ کنی.
- در تنظیمات، بخش «مدیریت گروه‌ها» برای ساخت/حذف گروه از قبل (حتی بدون کاربر) وجود داره.

**ساب‌لینک حرفه‌ای (نه یک متن خام)**
- وقتی همون ساب‌لینک (`/sub/{uuid}`) رو داخل یک **اپ کلاینت** (v2rayNG، Hiddify، NekoBox و…) باز
  کنی، دقیقاً مثل قبل خروجی base64 استاندارد می‌گیری — هیچ چیزی خراب نمی‌شه.
- اما اگه همون لینک رو توی یک **مرورگر معمولی** باز کنی، به‌جای یک رشته‌ی base64 بی‌معنی، یک
  **صفحه‌ی طراحی‌شده** می‌بینی: وضعیت اکانت، درصد مصرف، تاریخ انقضا، QR Code، دکمه‌ی کپی لینک
  تکی، و دکمه‌ی کپی خودِ ساب‌لینک. تشخیص کلاینت‌بودن/مرورگربودن از روی User-Agent و هدر Accept
  انجام می‌شه (و همیشه با پارامتر `?raw=1` می‌شه خروجی خام رو گرفت).

**امنیت و تنظیمات**
- تغییر رمز پنل از داخل خود پنل (بدون نیاز به redeploy) — رمز جدید هش و روی دیسک ذخیره می‌شه
  و رمز env variable رو override می‌کنه
- endpoint سلامت (`/health`) برای Railway health check

## محدودیت‌ها (صادقانه بگم)

- **داده‌ها (کاربران + رمز سفارشی) روی فایل JSON داخل کانتینر ذخیره می‌شن.** روی Railway،
  فایل‌سیستم کانتینر با هر دیپلوی جدید (نه ری‌استارت ساده) پاک می‌شه. برای ماندگاری، یک
  Railway Volume به مسیر `/app/app/data` وصل کن. اگه بخوای کمکت کنم بگو.
- شمارش ترافیک تقریبیه (هر ۵ ثانیه flush می‌شه)، نه دقیق بایت‌به‌بایت لحظه‌ای.
- شمارش «اتصال آنلاین» فقط in-memory هست و با هر ری‌استارت صفر می‌شه.
- فقط از `command=TCP` پشتیبانی می‌کنه (برای اکثر کاربردهای پروکسی/وب کافیه).

## مراحل دیپلوی

1. این فولدر رو به یک ریپازیتوری گیت‌هاب پوش کن.
2. در Railway: **New Project → Deploy from GitHub repo**.
3. توی تب **Variables** این‌ها رو ست کن:
   - `ADMIN_PASSWORD` = یک رمز قوی دلخواه (**حتماً عوضش کن**، پیش‌فرض `changeme123` هست —
     بعداً هم می‌تونی از داخل خود پنل، صفحه‌ی تنظیمات، عوضش کنی)
   - `WSPATH` = مسیر وب‌سوکت اولیه (اختیاری، پیش‌فرض `/tun`) — این فقط مقدار *اولیه* رو ست
     می‌کنه؛ بعد از اولین اجرا، مسیر واقعی از تنظیمات پنل (`/settings`) خونده می‌شه و از همونجا
     هم می‌تونی بدون Redeploy عوضش کنی
   - `PANEL_TITLE` = اسم دلخواه برای پنل (اختیاری)
4. توی **Settings → Networking**: فقط **Generate Domain** بزن. به TCP Proxy نیازی نیست.
5. بعد از دیپلوی، به آدرس `https://your-app.up.railway.app/login` برو و با `ADMIN_PASSWORD` وارد شو.
6. از صفحه‌ی «کاربران»، یک کاربر جدید بساز — لینک `vless://` و ساب‌لینک خودش با دامنه‌ی درست ساخته می‌شن.
7. یا لینک تکی رو مستقیم در کلاینت وارد کن، یا (پیشنهاد بهتر) **ساب‌لینک** رو در بخش
   Subscription کلاینت (v2rayNG / NekoBox / Hiddify) اضافه کن.

## چرا بدون TCP Proxy کار می‌کنه

- همه‌چیز (هم پنل، هم تانل VLESS) یک اپ وب استاندارد (uvicorn) روی پورت `$PORT` هست.
- تانل VLESS از طریق یک WebSocket endpoint (مسیر `WSPATH`) داخل همون اپ انجام می‌شه.
- چون این از نظر Railway «ترافیک HTTP» حساب می‌شه، از دامنه‌ی HTTPS پیش‌فرض
  (که TLS رو خودش در edge ترمینیت می‌کنه) رد می‌شه، دقیقاً مثل هر سایت معمولی دیگه.

## فایل‌ها

- `app/main.py` — روت‌های FastAPI (لاگین، نمای‌کلی، مدیریت کاربر، ساب‌لینک، QR، تنظیمات، وب‌سوکت VLESS)
- `app/vless.py` — پارس هدر پروتکل VLESS و رله ترافیک TCP↔WebSocket
- `app/storage.py` — ذخیره‌سازی کاربران/تنظیمات، منطق انقضا و محدودیت حجم، شمارش اتصال زنده
- `app/templates/` — `base.html` (لایوت سایدبار) + `overview.html` + `users.html` + `settings.html` + `login.html` + `sub.html` (صفحه‌ی عمومی ساب‌لینک)
- `app/static/style.css` — استایل تیره سفارشی
- `Dockerfile`, `run.sh`, `railway.json` — تنظیمات بیلد/اجرا روی Railway

## عیب‌یابی

- اگه دیپلوی ۵۰۲ داد: لاگ Deploy (نه Build) رو چک کن، معمولاً یعنی اپ crash کرده.
- اگه لاگین کار نکرد: مطمئن شو رمز رو دقیقاً همونی که در `ADMIN_PASSWORD` یا صفحه‌ی تنظیمات ست کردی وارد می‌کنی.
- اگه کلاینت وصل نشد: چک کن `path` توی لینک vless دقیقاً با «مسیر وب‌سوکت» ست‌شده در
  صفحه‌ی تنظیمات پنل مطابقت داشته باشه (لینک‌های ساخته‌شده از داخل پنل خودکار درسته؛ فقط اگه
  لینک رو دستی ساختی یا قدیمی کپی کردی ممکنه با تنظیمات جدید هم‌خونی نداشته باشه).
- اگه QR کد لود نشد: مطمئن شو پکیج‌های `qrcode` و `Pillow` توی build نصب شدن (توی requirements.txt هستن).
